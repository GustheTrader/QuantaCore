### TradingAgents (tauricresearch, Apache-2.0) — Python/LangGraph
- Pipeline: 4 analysts (market/sentiment/news/fundamentals, tool-calling) → bull/bear research debate (2×max_debate_rounds) → Research Manager (5-tier rating) → Trader (entry/stop/sizing proposal) → 3-way risk debate → Portfolio Manager → final PortfolioDecision (rating, thesis, price target, horizon)
- Research-only: "order sent to simulated exchange" — no live broker code
- Memory: decision log (~/.tradingagents/memory) + settlement against benchmark after holding_period_days + reflection injected into next PM prompt
- Backtest: `tradingagents backtest` ticker×date grid, alpha scoring, run_id resume
- Config: plain dict + TRADINGAGENTS_* env overrides; LLM via 15+ providers or **any OpenAI-compatible endpoint**; data via yfinance/EDGAR/FRED/AlphaVantage/Polymarket/Reddit/StockTwits
- Runtime: Python ≥3.10, LangGraph StateGraph, optional SqliteSaver checkpointing, streaming via propagate(stream_mode='values')

### The key design decision
**QuantaCore becomes TradingAgents' LLM gateway.** TradingAgents supports any OpenAI-compatible endpoint; Quanta already exposes /v1/chat/completions with encrypted, user-selected provider routes. One key store, one provider router, zero duplicated credentials, fully local-first. One small Quanta change required: /v1 must accept a loopback bearer token for the sidecar (today it guards on X-Quanta-Client header).

### Why a sidecar (not subprocess, not rewrite)
- Function-call boundary (propagate + pydantic schemas) is stable; CLI output is not parseable for streaming.
- Runs take minutes (multi-agent debates, recursion_limit 100) → need job semantics + SSE, which FastAPI gives for ~150 lines.
- Apache-2.0 permits tight vendoring; we treat it as a library, not a fork. No core-package edits except a thin event-emitting callback.

## 4. API contracts (new surface on eve.ts)

```
POST /api/trading/runs
  body: { ticker, trade_date?, asset_type: 'stock'|'crypto',
          portfolio?: { holdings[], cash }, config?: { debate_rounds, deep_think_llm, quick_think_llm } }
  resp: { run_id }
GET  /api/trading/runs/:id/events        → SSE stream of node/state deltas
GET  /api/trading/runs/:id               → final PortfolioDecision (pydantic → JSON)
GET  /api/trading/decisions              → ledger + settlement status + reflections
POST /api/trading/backtest
  body: { tickers[], start, end, every_days }  resp: { backtest_id }
GET  /api/trading/backtest/:id           → grid + alpha scores
GET  /api/trading/health                 → sidecar + engine + LLM-route check
```

Safety rules baked into the router:
1. Runs are research-only; the router never emits order intents to any external system.
2. Every decision row carries the full debate trail (auditable, no summary-only).
3. LLM cost surface: per-run token estimates shown BEFORE confirm in UI (debates × rounds × models).
4. Data-vendor failures are reported verbatim, never silently swallowed (GNOESIS desk rule).
